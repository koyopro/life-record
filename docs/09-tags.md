# 09. タグ分類

Item を横断的に分類する手段。[07-open-questions.md](07-open-questions.md) Q6 の結論として **タグを採用する**。

Remember The Milk のタグと同等の使い勝手を目指す。

---

## 9.1 なぜタグか

Q6 では「タグ」「プロジェクト（1対多）」「ラベル文字列」を比較した。タグを採用する理由は以下。

- 1つの Item が複数の観点に属することが実際に多い（例: 「買い物」かつ「急ぎ」）
- プロジェクト（1対多）だと、どちらか一方を選ばされる
- RTM ですでにタグを使っており、移行時に運用がそのまま持ち込める

なお `status` は「進行状態」、タグは「内容による分類」であり、役割が異なる。両者は併存する。

---

## 9.2 データモデル

正規化したタグテーブルと中間テーブルを持つ。

### tags

| カラム | 型 | 必須 | 説明 |
|---|---|---|---|
| id | UUID | Yes | タグID |
| name | text | Yes | タグ名。正規化済み。一意 |
| color | tag_color (enum) | No | 表示色。NULL は未設定（既定の色で出す） |
| created_at | timestamptz | Yes | 作成日時 |

### タグの色

固定の色見本（`shared/types/tag.ts` の `TAG_COLORS`）から選ぶ。
任意の色を許すと似た色が乱立しやすく、明暗対応も色の数だけ要るため。

色見本は 2 組ある。

- **RTM と同じ 24 色**（`RTM_TAG_COLORS`、`rtm-*`）。RTM の色見本と同じ
  6 列 × 4 行で、淡い色と濃い色が対になっている。RTM からの import で色を
  丸めずにそのまま使うために持つ（[05-operations.md](05-operations.md) の import）。
  RTM と同じ見え方にするため、明暗テーマで値を振らない。
- **独自の 12 色**（`LEGACY_TAG_COLORS`）。RTM の色見本を持つ前から使っている
  もので、すでに付いているタグがあるので残している（Postgres の enum は
  値を後から削れない）。新しく選ぶなら色がそろう RTM 側を使う想定で、
  色見本では RTM の 24 色を先に出す。

色見本 1 つは「背景色」と「その上に乗せる文字色」の組（`TAG_COLOR_SWATCHES`）。
RTM の淡い色は白文字だと読めないため、文字色を色ごとに持つ。
実際の値は `app/assets/css/main.css` の `--tag-*` / `--tag-*-fg` で、
TS 側と食い違っていないかは `tests/tag-color.spec.ts` が見張る。

一覧・詳細でのタグ表示は、RTM に倣い塗りつぶしの丸ピルで出す
（`#タグ名` ではなく `タグ名` のみ、背景が `--tag-*`・文字が `--tag-*-fg`）。
未設定のタグは既定の灰色（`--tag-default`）で出し、色が無い状態を作らない
（重要度の色分けと同じ考え方、[08-todo-management.md](08-todo-management.md) 8.1）。

### item_tags

| カラム | 型 | 必須 | 説明 |
|---|---|---|---|
| item_id | UUID | Yes | Item |
| tag_id | UUID | Yes | タグ |

主キーは `(item_id, tag_id)`。同じタグを同じ Item に二重に付けられない。

### 正規化しない案を採らない理由

`items.tags text[]` に配列で持つ案もあるが、以下の理由で採らない。

- タグ名の一括リネームができない（表記ゆれの修正が手作業になる）
- タグ一覧・件数の取得が煩雑になる
- 個人利用の規模では JOIN のコストが問題にならない

### タグ名の正規化

RTM に倣い、**大文字小文字を区別しない**。

- 前後の空白を除去する
- 小文字に変換して保存する
- 空白・カンマ・`#` は含められない（SmartAdd の区切りと衝突するため）
- 長さは 50 文字までとする

```text
"買い物" → "買い物"
"Shopping" → "shopping"
"  急ぎ  " → "急ぎ"
```

### 参照されなくなったタグ

最後の `item_tags` が消えた時点で、そのタグ自体も削除する。
使っていないタグが候補一覧に残り続けると、選択のノイズになるため。

### リネーム時の衝突

リネーム先の名前がすでに存在する場合、**エラーにせず2つのタグを統合する**。
表記ゆれを直す操作では衝突が起きて当然であり、そこで失敗すると
「先に片方を消してから」という手順を踏ませることになるため。

両方のタグが付いている Item は、統合後も1件として扱う（重複を作らない）。

## 9.3 機能

### 基本操作

- Item にタグを付ける / 外す
- タグで Item を絞り込む
- タグ一覧の表示（未完了 Item の件数つき）
- タグ名のリネーム（全 Item に反映される）
- タグの色を変える（`/tags` の色見本から選ぶ）
- タグの削除（全 Item から外れる）

### 絞り込み

| 条件 | 内容 |
|---|---|
| 単一タグ | そのタグが付いた Item |
| 複数タグ (AND) | 指定した全タグが付いた Item |
| 複数タグ (OR) | いずれかのタグが付いた Item |
| タグなし | タグが1つも付いていない Item |

初期実装では **単一タグ** と **タグなし** を対象とし、AND / OR は実際に必要になってから追加する。

「未完了 / 完了」の切り替えと組み合わせられるようにする（例: タグ「買い物」の未完了）。

### タグ一覧の画面

`/tags` に、使っているタグを Item 件数つきで並べる。ナビゲーションから入れる。
`g` `s`（[08-todo-management.md](08-todo-management.md) 8.4）は、この一覧を経由せず
タグを選ぶダイアログから直接タスク一覧へ移る別の入口。

- タグを押すと、そのタグで絞り込んだタスク一覧（`/?open=true&tag=`）へ移る。
  `open=true` で完了済みを除く
- **件数も未完了のものだけを数える**（`listTagsWithCount`）。押した先に並ぶ数と
  一致させるため。完了済みしか無くなったタグも、0件として一覧には残す
  （名前と色は残っており、完了側を見るときには使うため）
- そのタスク一覧の入力欄で追加すると、見ているタグを自動で付ける
  （そのまま追加すると絞り込みから外れて一覧から消えてしまうため）。
  期限も、書かなければ既定の「今日」ではなく「なし」にする
  （タグ一覧からの追加は「今日やること」に限らないため）
- 「タグなしのタスクを見る」も同じ場所に置く。絞り込みの入口をここに集める

色は各行の丸ボタンから、名前は隣の `✎` から変える。どちらも行の下をその場で
開く。別の画面へ移ると、どのタグを直していたのかを見失いやすいため。
削除の API はあるが、画面はまだ持たせていない（参照が0になれば自動で消える）。

#### 名前の変更

表記ゆれ（`shoping` → `shopping`）を直すための操作。付いている全 Item に
反映される。押す前に何が起きるかを入力欄の下に出す。

- 変更先に同じ名前のタグがあれば「1つにまとまります」と出す。
  統合はサーバー側の仕様（9.2）で、エラーにはならない
- 使えない名前（空白・カンマ・`#`）はサーバーと同じ正規化
  （`normalizeTagName`）で判定し、「変更」を押せなくする
- 色と違い、**応答を待ってから反映する**。Item 側が持っている名前まで
  変わる操作なので、先に出すと手元の写し（IndexedDB）と食い違う。
  済んだらタグ一覧と Item を取り直して揃える（`useTags` の `rename`）
- オフラインの手元集計（id が `local:`）は、サーバーの行を指せないので
  名前も色も変えられない

タグ一覧が取れるまでの間は、**直近の色を localStorage の控えから当てる**
（[12-offline.md](12-offline.md) 12.9）。リロード直後は手元の Item から数えた
タグを出しており、そこには色が無いため、控えが無いと数秒のあいだ全部が
灰色になる。

**選んだ色は、応答を待たずにその場で反映する**（`useTags` の `setColor`）。
待ってから反映すると、送信と取り直しの2往復ぶん押した色に変わらない。
色は表示のためだけのものなので先に出して構わない。当てる先は `useFetch` の
`data`（キーは `tags`）なので、一覧のカードや詳細のタグも同時に変わる。
送れなかったときは元の色へ戻し、その旨を画面に出す。

### 絞り込みの導線

タグの絞り込みは**すべての一覧で使えるようにする**（今日 / タスク）。
一覧コンポーネントがタグバーを持ち、画面ごとに書き分けない。

- 一覧の上部にタグバー（未完了 Item の件数つき）と「タグなし」を並べる
- カードに表示されているタグを押しても、その場で同じ絞り込みがかかる
- 同じタグをもう一度押すと解除する
- 絞り込みは URL（`?tag=`）に残す。再読み込みや共有で同じ状態に戻せる

### 入力

- Item 詳細・一覧から、タグ入力欄で追加する
- 入力中は既存タグを候補表示する（前方一致）
- 新しいタグ名を入力した場合はその場で作成する
- SmartAdd の `#` でも指定できる（9.4）

### キーボードショートカット

[08-todo-management.md](08-todo-management.md) 8.4 の表に以下を追加する。RTM の割り当てに準拠。

| キー | 操作 |
|---|---|
| `s` | 選択中のタスクのタグを変更 |
| `g` `s` | タグを選ぶダイアログを開く。タグ名はインクリメンタルに絞り込まれ、選ぶとそのタグのタスク一覧（`/?tag=`）へ移る |

RTM の「タグを変更」「タグに移動」に合わせて `s` / `g` `s` を使う。
`s` で複数選択している場合は、選択中の全タスクに適用する。

追加と削除は1つのダイアログでまとめて指定し、「適用」で一度に反映する。
付け外しを行き来する操作が多く、別々にすると開き直しが増えるため。

### 元に戻す

タグの変更は Undo（`u`）で戻せる。ただし一括で元の状態へ戻すのではなく、
**実際に変化した分だけを逆向きに付け外しする**。
タグは複数の Item で共有されるため、状態を丸ごと復元すると
他の操作で付いたタグまで巻き戻してしまう。

## 9.4 SmartAdd の `#`

[08-todo-management.md](08-todo-management.md) 8.5 で予約としていた `#` を、タグとして解釈するようにする。

```text
入力:  牛乳を買う #買い物 !2
結果:  title    = "牛乳を買う"
       tags     = ["買い物"]
       priority = 2
```

- `#` の直後から、空白までをタグ名として扱う
- 複数指定できる（`#買い物 #急ぎ`）
- 存在しないタグ名なら、その場で作成する
- タグ名に使えない文字（空白・カンマ）が来たらそこで区切る

> **注意:** RTM では `#` がリストとタグの両方に使われるが、このサービスにはリストの概念がない。
> `#` は常にタグとして解釈する。

### 入力中の候補

`#` を打つと、その場でタグの候補を出す（`ItemComposer`）。記号を打ってから
タグ名を思い出す手間を無くし、表記ゆれ（`shoping`）で新しいタグができるのを
防ぐため。本文エディタの絵文字候補（`:`。[11-scrapbox-notation.md](11-scrapbox-notation.md)）と
同じ操作にそろえる。

| 操作 | 動作 |
|---|---|
| `#` | すべてのタグを出す（多いときは先頭から8件） |
| 続けて入力 | 名前に含むものへ絞り込む |
| `↑` `↓` | 選ぶ |
| `Enter` / `Tab` | 確定する。`#タグ名 ` に置き換わり、続けて書ける |
| タップ / クリック | 同じく確定する |
| `Esc` | 候補だけ閉じる（書きかけは残す） |

- 候補を出している間の `Enter` は**確定**であって追加ではない。出せる候補が
  無ければこれまでどおり追加になる
- `#` からキャレットまでに区切り（空白・`,`・`#`）があれば出さない。
  切り方は SmartAdd のタグ記法（`#([^\s,#]+)`）と同じ
- **いま書いている `#...` 以外の**、すでに書いたタグは候補から外す。
  書きかけまで外すと、打ち終えた瞬間に候補から消えて確定できなくなる
- 日本語入力の変換中（`isComposing`）は横取りしない。変換の確定が
  タグの確定として扱われてしまうため

## 9.5 DDL

```sql
CREATE TYPE tag_color AS ENUM (
  -- RTM と同じ 24 色（淡い側・濃い側が対）
  'rtm-sky-pale', 'rtm-blue-pale', 'rtm-navy-pale',
  'rtm-purple-pale', 'rtm-mauve-pale', 'rtm-red-pale',
  'rtm-sky', 'rtm-blue', 'rtm-navy',
  'rtm-purple', 'rtm-mauve', 'rtm-red',
  'rtm-orange-pale', 'rtm-amber-pale', 'rtm-gold-pale',
  'rtm-olive-pale', 'rtm-green-pale', 'rtm-forest-pale',
  'rtm-orange', 'rtm-amber', 'rtm-gold',
  'rtm-olive', 'rtm-green', 'rtm-forest',
  -- RTM の色見本を持つ前から使っている独自の 12 色
  'red', 'orange', 'yellow', 'olive', 'green', 'teal',
  'blue', 'indigo', 'purple', 'pink', 'brown', 'gray'
);

CREATE TABLE tags (
  id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name       TEXT NOT NULL,
  color      tag_color,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT tags_name_unique UNIQUE (name),
  CONSTRAINT tags_name_not_blank CHECK (length(btrim(name)) > 0),
  CONSTRAINT tags_name_length CHECK (length(name) <= 50)
);

CREATE TABLE item_tags (
  item_id UUID NOT NULL REFERENCES items(id) ON DELETE CASCADE,
  tag_id  UUID NOT NULL REFERENCES tags(id)  ON DELETE CASCADE,
  PRIMARY KEY (item_id, tag_id)
);

-- タグから Item を引く経路（item_id が先頭の主キーでは効かない）
CREATE INDEX item_tags_tag_id_idx
  ON item_tags (tag_id);
```

Item の削除・タグの削除は、いずれも `ON DELETE CASCADE` で中間テーブルが片付く。
