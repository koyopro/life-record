# 14. ホーム画面アイコンからの導線（App Shortcuts）

ホーム画面のアイコンを長押しして、そのまま書き始められるようにする。

```text
アイコンを長押し → 「タスクを追加」     → 入力欄が開いた /add   → 書く → 追加
                → 「今日の日記を開く」 → その日の /diary/<日付> → 書く
```

書き始めるまでの間を詰めるための導線。アプリを開いて一覧が読み込まれるのを
待ち、入力欄や今日の日記へ移る、という手順を省く。

## 14.1 出し方

Web App Manifest の `shortcuts` で出す（nuxt.config.ts の `pwa.manifest`）。

```json
{
  "shortcuts": [
    {
      "name": "タスクを追加",
      "short_name": "追加",
      "description": "入力欄を開いた状態で起動する",
      "url": "/add",
      "icons": [{ "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" }]
    },
    {
      "name": "今日の日記を開く",
      "short_name": "日記",
      "description": "今日の日記を開いた状態で起動する",
      "url": "/diary/today",
      "icons": [{ "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" }]
    }
  ]
}
```

manifest だけで済み、Service Worker には何も足さない（共有の受付と同じ。
[13-share-target.md](13-share-target.md) 13.1）。

**置くのは「開いてすぐ書き始めたい」ものだけにする。** 読むだけならアイコンを
普通に押せば済む（`start_url` が `/today`）ので、長押しの先から選ぶ手間に
見合わない。増やすほど目当てを探す時間が延び、速さという目的が薄れる。

### 日付を含む行き先（`/diary/today`）

日記は日付ごとに URL が違うが、**manifest には日付を書けない**
（登録した日のまま固定されてしまう）。開いた時点の日付へ振り分けるだけの
経路（`app/pages/diary/today.vue`）を置き、そこを行き先にする。

- タイムゾーンは固定（Asia/Tokyo）なので、サーバーで振り分けても
  ブラウザで振り分けても同じ日になる
- オフラインでも Service Worker が返す殻から同じ判断ができる
  （[12-offline.md](12-offline.md) 12.2）。届いていない日記は控えから出る
- 履歴には残さない（`replace`）。戻ったときにここへ来て、また送り直される
  のを避ける
- `/diary/[date]` より先にこの経路が選ばれる（Nuxt は静的な区間を優先する）

出るのは**ホーム画面に追加（インストール）した場合だけ**で、manifest が
読めていることも要る。インストールできる状態の作り方（`<VitePwaManifest />` と
`useCredentials`）は 13.1 と共通なので、そちらを参照。

## 14.2 追加の画面（app/pages/add.vue）

置くのは3つだけ。

- 入力欄（一覧と同じ `ItemComposer`。**開いた時点でフォーカスする**）
- 追加できたものの一覧（タイトル。押すと Item の画面へ）
- 「追加したタスクを開く」「今日を見る」「タスクを見る」

一覧は載せない。一覧を出すと、その読み込みを待つあいだ画面が動き、
書いている途中で入力欄の位置がずれる。ここは書くためだけの画面にする。

### 「追加したタスクを開く」

**最後に追加したもの**（`/items/<id>`）へ移る。書いたあとに期限や本文を
足したくなることはよくあるが、そのために「追加しました」の一覧から目当てを
探して押させる必要はない。いちばん近い1つはボタンで開けるようにする。

続けて追加したときは、いま書いたばかりのほうへ移る（一覧の先頭と同じもの）。
まだ何も追加していないうちは行き先が無いので出さない。

### フォーカスすること

`ItemComposer` は既定では自動でフォーカスしない。一覧のある画面では、
フォーカスされていると一覧のキーボード操作（`j` / `k` など）が入力欄に
吸われ、スマートフォンでは勝手にキーボードが出るため
（[08-todo-management.md](08-todo-management.md) 8.4）。

この画面には一覧が無く、キーボードが出るのはむしろ望むところなので、
`autofocus` を付けて例外にする。狭い画面でも「＋」を押させずそのまま出す
（`inline`）。

#### キーボードは最初に触れたところで出す

ブラウザは**指で触れた流れの中でないとソフトキーボードを出さない**。
アイコンの長押しから開いたこの画面には触れた記録が無いので、カーソルは
入っていてもキーボードは出ない（フォーカスとキーボードは別物）。

そこで、**最初に画面のどこかへ触れた時点で入力欄へフォーカスし直す**
（`ItemComposer` の `focusFromTouch`）。触れた流れの中でのフォーカスなので
キーボードが出る。細い入力欄を狙って押す必要が無く、画面のどこを触っても
そのまま書き始められる。

- 拾うのは `click`。`pointerdown` で当てても、そのあとブラウザが既定の
  フォーカス移動（触れた場所へ移す）を行うので、当てたそばから外れる
- ボタン・リンク・入力欄そのものに触れたときは何もしない。その要素の操作を
  横取りしないため（入力欄はブラウザが自分でキーボードを出す）
- 効くのは最初の1回だけ。キーボードを閉じるつもりで画面を触ったときに、
  また開いてしまわないようにする

### 続けて追加できる

追加すると入力欄は空になり、フォーカスはそのまま残る。何が入ったかは
「追加しました」の一覧で確かめられるので、続けて書くのに画面を移らなくてよい。

### 入力欄の高さを、フォーカスが外れても変えない

`ItemComposer` は既定では、フォーカスが外れている間だけ下の行
（ヒントと「追加」）を畳んでいる（一覧の画面で場所を取らせないため）。
**入力欄をそのまま置く画面（`inline`。ここと `/share`）では畳まない。**

畳むと、入力欄からフォーカスが外れた瞬間に高さが 1 行ぶん（約 52px）縮む。
下に並べたボタンやリンクを押そうとすると、**押し下げた指の下から上へ逃げて
しまい**、離した場所にはもう何も無いので click が起きない。「追加したあと、
『今日を見る』や『タスクを見る』を押しても画面が変わらない」のはこれで、
フォーカスが外れたあとにもう一度押せば移れる、という分かりにくい挙動になる。

この画面は入力欄が最初からフォーカスされている（`autofocus`）ので、
ボタンを押すたびに必ずこれが起きる。畳んで空けられる 1 行より、
**押した先が動かないこと**を取る。

## 14.3 追加の経路

一覧の入力欄・共有の受付（`/share`）とまったく同じ経路を通る。
追加のためのデータモデルも API も足さない。

```text
app/pages/add.vue
  → buildItemDraft（app/utils/item-draft.ts）
  → useItemStore().create（IndexedDB へ書き、送信は列に積む）
```

- 初期状態は「未着手」（`status = backlog`）・期限は今日（buildItemDraft の既定）
- SmartAdd の記法（`^期限` `!重要度` `#タグ` `*繰り返し`）がそのまま効く
- オフラインでも追加でき、送信は繋がったときに行われる（[12-offline.md](12-offline.md)）

オフラインで開けるのも他の画面と同じ。`/add` への移動は Service Worker が
殻（`/offline-shell`）で受け、ブラウザ側でこの画面を描く（12.2）。

## 14.4 対応環境

- **Android Chrome** … 対応。主要な対象。
- **デスクトップの Chrome / Edge** … インストールすればタスクバー等の
  アイコンから同じ項目が出る。
- **iOS / iPadOS Safari** … manifest の `shortcuts` に未対応（長押ししても
  出ない）。`/add` を直接開くか、ショートカットアプリから開けば同じ画面になる。

なお、開いた時点でキーボードまで出すことはどのブラウザでもできない
（利用者が触れていない状態でソフトキーボードは出せない）。**最初に画面へ
触れたところで出す**ようにしてあるので、入力欄を狙って押す必要はない
（14.2「キーボードは最初に触れたところで出す」）。

## 14.5 実機での確認

1. Android Chrome で本番の URL を開き、「ホーム画面に追加」でインストールする
2. ホーム画面のアイコンを長押しし、**タスクを追加**・**今日の日記を開く** が
   出ることを確認する
3. 「タスクを追加」を選ぶと `/add` が開き、入力欄にカーソルが入っている。
   画面のどこかに触れるとキーボードが出て、そのまま書き始められる
4. 何か書いて「追加」を押すと、下に「追加しました」が出る
5. 「追加したタスクを開く」で、いま書いたものの画面（`/items/<id>`）が開く。
   **1回押しただけで移ること**（入力欄にカーソルが入ったままでも移れる）
6. 「タスクを見る」でその Item があり、「未着手」・期限が今日であることを確認する
7. 「今日の日記を開く」を選ぶと、その日の日記（`/diary/<今日>`）が開く。
   日付をまたいだ翌日も、登録し直さずに新しい日付が開くことを確認する

インストールせずに確認したいときは、`/add` と `/diary/today` を直接開けば
同じ画面を試せる。
