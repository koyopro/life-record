# 01. 概要・基本方針

## 1.1 背景

現在、個人の情報管理に複数のサービスを使い分けている。

- TODO管理
- メモ・知識管理
- 日記
- 画像を含む記録
- その他の個人的な情報

サービス間で内容をコピーする作業が発生することがあり、管理方法が分散している。

そこで、これらを一つにまとめた **自分専用の個人用記録サービス** を作る。

既存サービスを完全に再現することを目的とせず、自分の使い方に合わせて必要な機能だけを持つ、シンプルで長期間使えるサービスを目指す。

## 1.2 基本方針

- 個人利用を前提とする
- 自分が日常的に使いやすいことを最優先する
- 最初から大規模なサービスとして設計しない
- データを長期間保持できることを重視する
- 特定のSaaSに強く依存しすぎない
- Markdown的な自由度の高い記録体験を目指す
- PC・スマートフォンの両方から使えるようにする
- まず最小限の機能を作り、実際に使いながら拡張する

## 1.3 参考にしているサービス・用途

現在の用途として、主に以下を一つのサービスに統合したい。

- Remember The Milk 的なTODO管理
- Scrapbox 的な自由なメモ・情報整理
- Google Keep 的な素早いメモ（特にスマートフォン）
- 日記
- 画像を含む個人的な記録

特に、スマートフォンから気軽に情報を投入し、後からPCで整理できる体験を重視する。

## 1.4 このサービスの中心にある考え方

一般的なTODOアプリと異なり、**「TODO そのもの」と「その TODO について何をしたかの記録」を分離する**。

```text
Item (TODO)          「個人用アプリのDB設計」
  ├── Section  2026-08-18  ItemとDiaryの関係を整理した。
  ├── Section  2026-08-19  Sectionを文章単位として扱う方針に決めた。
  └── Section  2026-08-20  DB設計を確定した。
```

これにより、1つのTODOが複数日にまたがって進行しても、日々の作業の積み重ねをそのまま記録として残せる。

さらに、Diary（1日1ページの日記）と Section は同じ「日付」を持つため、

- 日記から「その日に作業したTODO」を辿る
- TODOから「作業した日の日記」を辿る

という双方向のナビゲーションが、中間テーブルなしで成立する。

詳細は [02-data-model.md](02-data-model.md) を参照。

## 1.5 最初に検証したい体験

最初のマイルストーンでは、以下の流れが自然に使えることを確認する。

> スマートフォンでItemを素早く追加
> → Inboxに蓄積
> → PC等で後から整理
> → status を変更
> → 作業したらその日の Section を書く
> → 完了したら Closed

この基本フローが快適であることを最優先する。

### 最重要の評価ポイント

「DB設計を完璧にしてから作る」のではなく、**最初の操作体験を早く実装して検証する**。

特に以下の2点を初期開発における最重要事項とする。

> 「思いついたことをスマートフォンですぐ記録できるか」

> 「後からPCで整理するのが面倒ではないか」
