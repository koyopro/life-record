# 11. 本文の記法（Scrapbox 記法）

`Section.body` と `Diary.body` は、**Scrapbox 記法を基本としたプレーンテキスト**とする。

Markdown には寄せない。Scrapbox の

> 軽量な記法で素早く書ける
> すべての内容がプレーンテキストとして残る

という考え方を採るのが目的であり、Markdown との互換性より **Scrapbox 記法との一貫性**を優先する。

---

## 11.1 基本方針

- 本文はプレーンテキストとして DB に保存する。HTML やリッチテキスト JSON にはしない
- 記法はできる限り Scrapbox に合わせる
- Markdown 記法を混在させない
- 表示時に記法を HTML へ変換する
- 編集時は元の記法テキストを直接編集する
- 未対応の記法は、そのままのテキストとして扱う
- パーサーは記法を追加できる構造にする
- ユーザー入力を HTML として実行させない（11.10）

### 行頭の空白を正規化しない

Scrapbox では**行頭の空白が階層を表す**ため、保存時に削ったり詰めたりしない。
入力されたテキストをそのまま保存する。

---

## 11.2 記法の確認元

記法は記憶で書かず、Cosense（Scrapbox）公式ヘルプの生テキストを取得して確認した。

| 内容 | 参照元 |
|---|---|
| 全般 | `https://scrapbox.io/api/pages/help-jp/その他の書き方/text` |
| 文字装飾 | `https://scrapbox.io/api/pages/help-jp/文字装飾記法/text` |
| コードブロック | `https://scrapbox.io/api/pages/help-jp/コードブロック/text` |
| 箇条書き・リンク | `https://scrapbox.io/api/pages/help-jp/ブラケティング/text` |
| 見出し | `https://scrapbox.io/api/pages/help-jp/見出し/text` |

### 確認して分かった重要な点

**Scrapbox に見出しを作る機能は存在しない。**
公式ヘルプ「見出し」にはこう書かれている。

> Scrapboxには見出しを作る機能はありません
> 見出しが作れるほど独立した内容であれば、別のページに切り出す方が良いです
> 見出しはありませんが、画像や文字を大きくする機能は存在します

したがって、このサービスでも**見出し記法は作らない**。
`[* 強調]` の `*` の数で文字が大きくなる、という Scrapbox の文字装飾記法をそのまま使う。
Markdown の `#` `##` は採用しない。

## 11.3 対応する記法

MVP では以下を実装する。

### 改行・空行

そのまま保持する。1行がそのまま1行として表示される。

### 箇条書き

行頭の空白（スペース／タブ）の数で階層を表す。全角スペースも半角と同じ1段として扱う
（日本語入力で変換の際に紛れ込みやすいため）。

```text
買い物
 牛乳
 パン
  食パン
```

→ 「買い物」の下に「牛乳」「パン」、「パン」の下に「食パン」。

### 文字装飾（見出しの代わり）

```text
[* 強調]                    → 太字＋少し大きい
[**** もっと大きな文字]     → * の数だけ大きくなる
[/ 斜体文字]
[- 打ち消し]
[_ 下線]
[-/*** 打ち消し斜体大きな文字]   ← 記号は組み合わせられる
[[強調]]                    → [* 強調] と同じ扱い
```

`*` の数を文字サイズに対応させる。`*` がなければ太字にしない
（`[/ 斜体]` は斜体だけ）。

Scrapbox は `!"#%&'()*+,-./{|}<>_~` を装飾記号として受け付け、CSS クラスとして出力する。
このサービスでは意味を与えた `* / - _` だけを解釈し、残りは無視する。

### リンク

```text
[https://example.com]              → URL そのものを表示
[https://example.com Example]      → 表示文字列つき
[Example https://example.com]      → 逆順でも同じ
https://example.com                → 裸の URL もリンクにする
[ページ名]                          → ページリンク
```

ページの概念がまだないため、`[ページ名]` は遷移先を持たず、印だけを付けて表示する。
将来ページを持つときに、そのままリンクへ変えられる。

### アプリ内のページへのリンク

日記とタスクは、本文の中から互いを直接指せる。画像リンク（`[/images/xxx]`、11.7）と
同じ「角括弧＋アプリの相対パス」の形で表す。独自記法を増やさず、既存のリンク記法
（`[URL]` / `[URL 表示文字列]`）がそのまま使えるようにするための選び方。

```text
[/items/<Item の id>]                    → タスクへのリンク（表示は path そのもの）
[/items/<Item の id> 買い物リストを作る]   → 表示文字列つき
[/diary/2026-08-19]                      → 日記へのリンク
[/diary/2026-08-19 今日の日記]            → 表示文字列つき
```

- `/items/<id>` は id が UUID の形をしているときだけ、`/diary/<date>` は
  `YYYY-MM-DD` が実在する日付のときだけリンクとして認識する。
  それ以外はただの文字列として扱う
- id・日付は、詳細画面や日記のアドレスバー（URL）からそのままコピーできる
- 外部リンクと違い、新しいタブは開かず同じタブの中で遷移する
  （日記とタスクを行き来する用途のため）
- ページ名で引く仕組み（`[ページ名]` の将来対応）とは別。
  こちらは id・日付という確定した識別子で直接指す

id を手で書かなくて済むよう、日記の「この日にやったこと」の項目は本文へドラッグ
できる。ドロップすると、そのタスクへのリンク（`[/items/<id> タイトル]`）を
本文のカーソル位置へ挿入する。

### コード

```text
`インラインコード`
```

```text
code:hello.js
  function () {
    alert(1)
  }
```

`code:` の行から**1段深い行**がコードブロックの中身。
中身は他の記法として解釈しない。

リストの中に埋め込んだ場合、コードブロックはその字下げを保つ
（一覧などの抜粋表示でも、コードの字下げごと保持する）。

中身の空行は、ブロックの基準の字下げ（`code:` 行の字下げ + 1）と
同じ間だけ続きとみなす。合わない字下げの空行が来ると、そこで
コードブロックを抜ける。

### 画像

```text
[https://example.com/a.png]                       → 画像
[[https://example.com/a.png]]                     → 横幅いっぱいの画像
[https://example.com https://example.com/a.png]   → リンク付き画像（逆順も可）
```

Scrapbox に合わせ、**画像も角括弧のリンク記法**で表す。
`[image:ID]` のような独自記法は作らない。

表示の大きさは記法で変える。`[画像URL]` は文章に混ぜる画像として高さ 300px で
頭打ちにし、`[[画像URL]]` は横幅いっぱいに広げて高さの頭打ちを外す。
どちらも**縦横比は変えない**（切り取りもしない）。横幅いっぱいのまま高さだけ
頭打ちにすると、縦長の画像が潰れて見えるため。

### 引用

行頭に `>` を書く。複数行の引用は各行に `>` を書く（Scrapbox と同じ）。
表示上は、続く引用行をひとつの枠にまとめる。

```text
> 引用の1行目
> 引用の2行目
```

### ハッシュタグ

`#タグ` を書くと印が付く。Item のタグ（[09-tags.md](09-tags.md)）とは今のところ連動しない。

## 11.4 対応しない記法

Scrapbox にはあるが、このサービスでは今のところ解釈せず、そのままのテキストとして表示する。

| 記法 | 内容 |
|---|---|
| `[ページ名.icon]` | アイコン |
| `table:名前` | テーブル |
| `[$ 数式]` | 数式 |
| `/プロジェクト名/ページ名` | 別プロジェクトへのリンク |
| 行頭の `$` `%` | コマンドライン |

## 11.5 パーサーの構造

**記法 → AST（中間表現）→ HTML** の順に変換する。

```text
shared/utils/scrapbox/
  types.ts   AST の定義
  parse.ts   記法 → AST
  render.ts  AST → HTML
```

文字列置換だけで HTML を作らない。

```text
[* 重要 [https://example.com リンク]]
```

のように記法が入れ子になったとき、置換では対応する括弧を見つけられず破綻するため。
角括弧は深さを数えて対応を取る。

### 1行 = 1要素

パース結果は、入力の行数と必ず一致する。
カーソルのある行だけをテキストに戻すため（11.6）、行と表示が1対1でないと成立しない。

箇条書きの階層は入れ子の `<ul>` ではなく、各行の字下げを CSS の余白で表す。
Scrapbox 自身も行単位で描画しており、この方が編集との相性がよい。

### 行頭（prefix）と中身（content）

各行は、**表示では文字を出さず余白に置き換える行頭**と、その後ろの中身に分けて持つ。

| 行 | 行頭 | 中身 |
|---|---|---|
| `  買い物` | `  `（字下げ） | `買い物` |
| `> 引用` | `> ` | `引用` |
| `code:hello.js` | `code:` | `hello.js` |
| コードブロックの中身 | ブロックの基準までの空白 | それより深い字下げを含む中身 |

`行頭 + 中身 === 元の行` が常に成り立つ。保存されるのは元の行のままで、
分けて持つのは表示と編集のためだけ（11.6）。

- **行**: 通常行 / 引用 / `code:` の行 / コードブロックの中身
- **インライン**: 行の中身。装飾・リンク・画像・コード・ハッシュタグ

角括弧の中身は、次の順で判定する。

1. `[[...]]` → 画像 URL なら大きい画像、それ以外は強調
2. 装飾記号＋空白で始まる → 文字装飾
3. 2語で「画像URL＋URL」→ リンク付き画像
4. 先頭または末尾が URL → リンク
5. 単体が画像 URL → 画像
6. 単体が URL → リンク
7. それ以外 → ページリンク

## 11.6 編集 UI

Notion のような WYSIWYG にはしない。Scrapbox と同じく、
**記法を含むプレーンテキストを直接編集する**。

### 行単位で切り替える

Scrapbox と同じく、**行ごとに**表示を切り替える。

| 行 | 表示 |
|---|---|
| カーソルのある行 | 記法をそのままのテキストとして編集 |
| それ以外の行 | 記法を解釈した表示 |

本文全体を一度にテキストへ戻さない。書いている場所の記法だけが見え、
周りは仕上がりのまま読めるので、書きながら全体を確認できる。

そのため、**パーサーは1行が必ず1要素に対応する構造**にしている
（11.5）。行と表示がずれると、カーソル行だけを差し替えられない。

### 行頭は入力欄に入れない

カーソルの有無で**文字の開始位置が変わってはいけない**。
表示側は字下げを余白（1段 1.25rem）で表すのに対し、入力欄に行頭の空白を
そのまま入れると、その行だけ文字が空白の幅ぶんずれてしまう。引用の `>` と
`code:` でも同じことが起きる（表示では枠線や見出しに置き換わり、文字は出ない）。

そこで、**行頭（11.5）は入力欄にも入れない**。入力欄には中身だけを入れ、
その外枠に表示側と同じクラス・同じ字下げを付けて、同じ幅の余白を作る。
字送りが変わらないよう、コードブロックの中では入力欄も等幅にする。

行頭は文字として見えないので、キーで操作する。

- 空白や `>` を行頭に打つと、その文字は行頭（＝余白）に移る
- 行頭にカーソルがあるときの `Backspace` は、まず行頭を1段外す

コピーは Scrapbox と同じく、記法込みの生テキストを渡す。行全体を選んで
コピーすると、余白にしている行頭（字下げ・`>` ・`code:`）も含めて貼り付け
られる。複数行にまたがる選択も同様。1行内の部分選択（コードの中身の
一部だけ選ぶなど）は、ブラウザの既定のコピーのまま。

### キー操作

| キー | 動作 |
|---|---|
| クリック / `y` | その行の編集に切り替える |
| `[` | `]` も添える。カーソルは `[` の直後 |
| `Enter` | 行を分割する。前の行の字下げと `>` を引き継ぐ |
| `Backspace` / `Ctrl`+`H`（行頭） | 字下げ・`>` ・`code:` を1段外す。無ければ前の行と結合する（macOS の `Ctrl`+`H` は Backspace。1文字消すのは入力欄に任せ、改行を消して繋ぐところだけ受け持つ） |
| `Delete` / `Ctrl`+`D`（行末） | 次の行と結合する。コードブロック中の空行では、結合の代わりにその行からコードブロックを抜ける |
| `Ctrl`+`K`（空行） | 改行を消して次の行と結合する（`Ctrl`+`D` と同じ） |
| `↑` `↓`（行端） | 前後の行へ移る |
| `Ctrl`+`↑` / `↓` | 行を1つだけ上下に動かす |
| `Option`+`↑` / `↓` | 段落を、同じ階層の隣の段落と入れ替える |
| `Tab` / `Shift`+`Tab` | 字下げを1段増やす / 減らす。複数行選択中は選んだ行すべてに効く |
| `Ctrl`+`T` | 今日の日付（`YYYY-MM-DD`）を挿入。1.5秒以内・カーソルを動かさずに続けて押すと、挿入した日付を日記へのリンク（`[/diary/YYYY-MM-DD]`、「アプリ内のページへのリンク」）に差し替える |
| `Esc` | 編集をやめて表示に戻す。複数行選択中は選択だけ解除する |
| `Cmd`+`A` | 本文全体を選択する。`Ctrl`+`A` は含めない（macOS で行頭へ移動する Emacs 風操作のため） |
| `Shift`+`↑` `↓` `←` `→`（行端） | 前後の行を選択に加える。行内をまだ選べるうちはブラウザの既定の選択のまま |
| `Cmd`/`Ctrl`+`Z` | 直前の変更を取り消す |
| `Cmd`/`Ctrl`+`Shift`+`Z`（`Ctrl`+`Y`） | 取り消した変更をやり直す |

複数行の選択は、1行編集用の入力欄（textarea）を抜けて、表示側の DOM に対する
ブラウザの選択として組み立てる。このとき、**画像だけの行**（`[[画像URL]]` や
アイコンだけの行）には文字が1つも無い。選択の端点をテキストノードに限ると
そういう行をまたぐ選択が作れず、入力欄からも抜けたあとなので、本文から
フォーカスが外れたように見えてしまう。文字を持たない行では、行の要素
そのものを選択の端点にする。

### 取り消し（Undo / Redo）

ブラウザ標準の取り消しには頼らず、自前の履歴として持つ。

入力欄（textarea）は行ごとに作り直さず1つを使い回しており（「入力欄は1つを
使い回す」）、行を移るたびにその値をプログラムから書き換えている。
`.value` を直接書き換えるとブラウザが持つ取り消し履歴はそこで切れるため、
標準のままでは「行を移ると直前の修正が戻せない」「複数行への操作
（`Tab` での字下げなど）がそもそも履歴に乗らない」といった穴ができる。

本文の変更はすべて `commit()` を通るので、そこで変更前の内容を積む。

- 1文字ずつの通常入力は、続けて打っている間（0.7秒以内・同じ行）は
  1つの取り消し単位にまとめる。1文字ずつ戻るのは操作感が悪いため
- それ以外（`Enter` での分割、`Backspace` での結合、`Tab`、行・段落の移動、
  貼り付け、画像やリンクの挿入など）は、常に単独の取り消し単位にする
- 戻したあとは、その変更が起きた行の編集状態へカーソルごと戻す
- 変換中（IME）は取り消しを受け付けない。変換の取り消しと衝突するため

行を結合するとき、後ろの行の行頭は落とす。表示では余白なので、
繋げたときに空白の文字として行の途中に残ってはおかしい。

### 行と段落の移動

Scrapbox に合わせて2種類を用意する。**段落**は、その行と、続く
より深い字下げの行（＝ぶら下がっている行）をまとめたもの。

- `Ctrl`+`↑` / `↓` … その行だけを動かす。字下げは変えない
- `Option`+`↑` / `↓` … 段落ごと動かす。**同じ階層**の隣の段落と入れ替える

段落の移動は同じ深さの段落どうしでのみ行い、**深さは変えない**。
隣にあるのが同じ深さの段落でないとき（親の直下で先頭の子、階層の最後の子）
は動かさない。深さを変えたいときは字下げ（`Tab`）を使う。階層をまたいで
並べ替えたいときは行の移動（`Ctrl`+`↑` / `↓`）を使う。

1行ずつずらさないのは、隣の段落の途中に割り込んでしまうため。上へ動かす
ときは、自分より深い行（＝手前の段落にぶら下がっている行）を飛ばして遡り、
最初に見つかった同じ深さの行を相手にする。先に浅い行が来たら、それは親なので
入れ替える相手はいない。

コードブロックは見出しと中身でひとまとまりなので、字下げに関わらず
切り離さない。中身の行を `Option`+`↑` / `↓` で動かしたときは、
ブロックの外へは出さない（中で入れ替えるだけ）。

`[` で閉じ括弧を添えるのは、Scrapbox の記法がほぼ角括弧で、
閉じ忘れると記法として成立しないため。選択範囲があるときはそれを囲む。

`Delete` / `Ctrl`+`D` は「カーソルより後ろを1文字消す」操作。行末にあるのは
改行なので、次の行と結合する。行の途中ではブラウザ既定の削除に任せる。

キー判定には Vue のキー修飾子を使わず `event.key` を直接見る。
`.delete` が Backspace の別名になっているなど、名前と実際のキーが
一致しない箇所があり、取り違えると事故になるため。

日本語入力の変換中は `Enter` を横取りしない。変換の確定が行の分割として
扱われてしまうため、`compositionstart` / `compositionend` で判定する。

### 入力欄は1つを使い回す

編集中の行に入力欄を出すが、**行ごとに作り直さない**。表示位置は
flex の `order` で動かし、要素そのものは1つのまま保つ。

行を移るたびに要素を作り直すと、`Enter` で行を分けた直後に入力欄が
差し替わってフォーカスが外れ、続きが打てなくなる（実際にそうなった）。

同じ理由で、値の反映に `v-model` は使わず入力欄の値を直接読む。
`v-model` と `@input` を併用すると、どちらが先に走るかで
一手ぶん古い値を書き戻すことがある。

保存されるのは常に入力したままのテキスト。
将来、入力補助を足すことはできるが、保存するデータは変えない。

## 11.7 画像とS3

画像本体は S3 に置く（[03-functional-spec.md](03-functional-spec.md) 3.5）。
本文からは、Scrapbox の画像記法（角括弧のURL）で参照する。

```text
[/images/<画像ID>.png]
```

### なぜアプリからの相対パスか

- **独自記法を作らない** — Scrapbox の `[画像URL]` の形をそのまま使えるため、
  記法の一貫性が保てる
- **ホスト名を本文に埋め込まない** — 絶対 URL で保存すると、ドメインを変えたときに
  全ての本文を書き換えることになる。長期利用とデータの持ち出しやすさを重視する方針
  （[05-operations.md](05-operations.md)）に反する
- **エクスポート時は接頭辞を置換するだけで済む** — `/images/` を配布先の URL に
  置き換えれば、他のツールでも画像が解決できる

> **トレードオフ:** Scrapbox では `/プロジェクト名/ページ名` が別プロジェクトへの
> リンクを意味するため、`/images/...` は記法として衝突する。
> このサービスにプロジェクトの概念がないため、実害はないと判断して受け入れる。

### アップロードの流れ

1. `POST /api/images` で、署名付きの PUT 先と `/images/<ID>.<拡張子>` を受け取る
2. ブラウザから S3 へ直接 PUT する（画像は Function を通らない）
3. 本文へ `[/images/<ID>.<拡張子>]` を挿入する
4. 表示時、`GET /images/<ID>.<拡張子>` が S3 の署名付き取得URLへ 302 で返す

S3 のオブジェクトキーは `images/<ID>.<拡張子>`。本文のパスと1対1に
対応させてあるので、対応表を持たずに解決できる。

詳細は [07-open-questions.md](07-open-questions.md) Q4。

## 11.8 アイコン（`:name:`）

絵文字だけでは足りない印（プロジェクトのロゴ・自作のスタンプなど）を、
自分で登録して本文に置けるようにする。Notion のカスタム絵文字にあたる。

```text
入力:  今日はリリース :party-parrot:
表示:  今日はリリース <画像>
```

### 記法と解決

本文には **`:name:` とだけ書く**。画像のパスは書かない。

- 記法を読む時点では、登録されているかどうか分からない（一覧はサーバーに
  ある）。パーサは形だけを取り、**画像にするか文字のまま出すかは描画時に
  決める**（`renderLine` の `options.icons`）
- 登録が無ければ、**書かれたままの文字**を出す。`12:30:45` のような
  普通の文章が壊れないのはこのため。大文字（`:Hoge:`）で書いても引けるが、
  出せないときは書いた形のまま残す
- 名前に使えるのは英数字・`_`・`-` の32文字まで。絵文字のショートコードと
  同じ範囲にそろえる（`shared/types/icon.ts`）
- コードの中（`` ` `` で囲んだ部分・コードブロック）では記法として扱わない

パスではなく名前を書くのは、リンクと同じ理由（11.7「なぜアプリからの
相対パスか」）に加えて、**画像を差し替えても本文を直さなくて済む**ため。
同じ名前で登録し直せば、その名前を書いた全ての本文が新しい画像になる。

### 登録と削除（`/icons`）

画像を選んで名前を付けると登録される。画像そのものは本文中の画像と同じ
経路（`POST /api/images` → S3 へ直接 PUT）で送り、アイコンの表には
その場所（`/images/<ID>.<拡張子>`）と名前だけを持つ。置き場を別に作らない。

- 同じ名前で登録すると**画像を差し替える**（消してから入れ直さなくてよい）
- 削除しても本文は書き換えない。書いた `:name:` は文字として残る。
  本文を追いかけて消すと、書いたものを勝手に変えることになるため
- 参照されなくなった画像は S3 に残る。タグと違って自動では消さない
  （[06-roadmap.md](06-roadmap.md) Milestone 8「孤児オブジェクト」と同じ扱い）

### 入力（`:` の候補）

`:` を打つと出る候補（絵文字ピッカー）に混ぜて出す。**登録したアイコンを
先に、絵文字を後に**並べる。登録したものは数が少なく、探しているのは
たいていそちらなので、絵文字に埋もれさせない。

- 絵文字は選んだ時点で文字（Unicode）に置き換わる。アイコンは文字が無いので
  `:name:` を本文に残す
- 上下で選び、`Enter` / `Tab` で確定する（絵文字と同じ）

### 表示が届くまで

対応表は `/api/icons` から取る。リロードは Service Worker が返す殻から
始まるため、届くまでの間は `:name:` が文字のまま見える。直近の対応表を
localStorage に控え、その間はこれで描く（[12-offline.md](12-offline.md) 12.9。
タグの色と同じ扱い）。

## 11.9 保存するもの

DB に入るのは、**ユーザーが入力したテキストそのまま**。

- HTML は保存しない
- リッチテキスト JSON も保存しない
- 記法の正規化もしない

表示のたびに変換する。変換結果を保存しないので、記法の解釈を後から変えても
過去の本文がそのまま生き続ける。

## 11.10 XSS 対策

本文はユーザーが書いた文字列であり、そのまま HTML にすると危険。

- **すべてのテキストをエスケープしてから**組み立てる（`&<>"'`）
- `href` / `src` に入れる URL は、`http(s)://` とアプリ相対パスだけを通す。
  `javascript:` などは通さず、リンクにせずテキストとして出す
- コードブロック・インラインコードの中身も同じくエスケープする

レンダラの出力は上記を満たしたうえで組み立てているため、表示側で `v-html` を使ってよい。

### 確認した入力

| 入力 | 結果 |
|---|---|
| `<script>alert(1)</script>` | エスケープされて文字として表示 |
| `[<img src=x onerror=alert(1)> https://example.com]` | タグがエスケープされ、リンクのテキストになる |
| `[javascript:alert(1) クリック]` | リンクにならない |
| `[javascript:alert(1).png]` | 画像にならない |
