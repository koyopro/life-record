# 11. 本文の記法（Scrapbox 記法）

`Section.body` と `Diary.body` は、**Scrapbox 記法を基本としたプレーンテキスト**とする。

Markdown には寄せない。Scrapbox の

> 軽量な記法で素早く書ける
> すべての内容がプレーンテキストとして残る

という考え方を採るのが目的であり、Markdown との互換性より **Scrapbox 記法との一貫性**を優先する。

---

## 11.1 基本方針

- 本文はプレーンテキストとして DB に保存する。HTML やリッチテキスト JSON にはしない
- 記法はできる限り Scrapbox に合わせる
- Markdown 記法を混在させない
- 表示時に記法を HTML へ変換する
- 編集時は元の記法テキストを直接編集する
- 未対応の記法は、そのままのテキストとして扱う
- パーサーは記法を追加できる構造にする
- ユーザー入力を HTML として実行させない（11.9）

### 行頭の空白を正規化しない

Scrapbox では**行頭の空白が階層を表す**ため、保存時に削ったり詰めたりしない。
入力されたテキストをそのまま保存する。

---

## 11.2 記法の確認元

記法は記憶で書かず、Cosense（Scrapbox）公式ヘルプの生テキストを取得して確認した。

| 内容 | 参照元 |
|---|---|
| 全般 | `https://scrapbox.io/api/pages/help-jp/その他の書き方/text` |
| 文字装飾 | `https://scrapbox.io/api/pages/help-jp/文字装飾記法/text` |
| コードブロック | `https://scrapbox.io/api/pages/help-jp/コードブロック/text` |
| 箇条書き・リンク | `https://scrapbox.io/api/pages/help-jp/ブラケティング/text` |
| 見出し | `https://scrapbox.io/api/pages/help-jp/見出し/text` |

### 確認して分かった重要な点

**Scrapbox に見出しを作る機能は存在しない。**
公式ヘルプ「見出し」にはこう書かれている。

> Scrapboxには見出しを作る機能はありません
> 見出しが作れるほど独立した内容であれば、別のページに切り出す方が良いです
> 見出しはありませんが、画像や文字を大きくする機能は存在します

したがって、このサービスでも**見出し記法は作らない**。
`[* 強調]` の `*` の数で文字が大きくなる、という Scrapbox の文字装飾記法をそのまま使う。
Markdown の `#` `##` は採用しない。

---

## 11.3 対応する記法

MVP では以下を実装する。

### 改行・空行

そのまま保持する。1行がそのまま1行として表示される。

### 箇条書き

行頭の空白（スペース／タブ）の数で階層を表す。

```text
買い物
 牛乳
 パン
  食パン
```

→ 「買い物」の下に「牛乳」「パン」、「パン」の下に「食パン」。

### 文字装飾（見出しの代わり）

```text
[* 強調]                    → 太字＋少し大きい
[**** もっと大きな文字]     → * の数だけ大きくなる
[/ 斜体文字]
[- 打ち消し]
[_ 下線]
[-/*** 打ち消し斜体大きな文字]   ← 記号は組み合わせられる
[[強調]]                    → [* 強調] と同じ扱い
```

`*` の数を文字サイズに対応させる。`*` がなければ太字にしない
（`[/ 斜体]` は斜体だけ）。

Scrapbox は `!"#%&'()*+,-./{|}<>_~` を装飾記号として受け付け、CSS クラスとして出力する。
このサービスでは意味を与えた `* / - _` だけを解釈し、残りは無視する。

### リンク

```text
[https://example.com]              → URL そのものを表示
[https://example.com Example]      → 表示文字列つき
[Example https://example.com]      → 逆順でも同じ
https://example.com                → 裸の URL もリンクにする
[ページ名]                          → ページリンク
```

ページの概念がまだないため、`[ページ名]` は遷移先を持たず、印だけを付けて表示する。
将来ページを持つときに、そのままリンクへ変えられる。

### コード

```text
`インラインコード`
```

```text
code:hello.js
  function () {
    alert(1)
  }
```

`code:` の行から**1段深い行**がコードブロックの中身。
中身は他の記法として解釈しない。

### 画像

```text
[https://example.com/a.png]                       → 画像
[[https://example.com/a.png]]                     → 横幅いっぱいの画像
[https://example.com https://example.com/a.png]   → リンク付き画像（逆順も可）
```

Scrapbox に合わせ、**画像も角括弧のリンク記法**で表す。
`[image:ID]` のような独自記法は作らない。

### 引用

行頭に `>` を書く。複数行の引用は各行に `>` を書く（Scrapbox と同じ）。
表示上は、続く引用行をひとつの枠にまとめる。

```text
> 引用の1行目
> 引用の2行目
```

### ハッシュタグ

`#タグ` を書くと印が付く。Item のタグ（[09-tags.md](09-tags.md)）とは今のところ連動しない。

---

## 11.4 対応しない記法

Scrapbox にはあるが、このサービスでは今のところ解釈せず、そのままのテキストとして表示する。

| 記法 | 内容 |
|---|---|
| `[ページ名.icon]` | アイコン |
| `table:名前` | テーブル |
| `[$ 数式]` | 数式 |
| `/プロジェクト名/ページ名` | 別プロジェクトへのリンク |
| 行頭の `$` `%` | コマンドライン |

---

## 11.5 パーサーの構造

**記法 → AST（中間表現）→ HTML** の順に変換する。

```text
shared/utils/scrapbox/
  types.ts   AST の定義
  parse.ts   記法 → AST
  render.ts  AST → HTML
```

文字列置換だけで HTML を作らない。

```text
[* 重要 [https://example.com リンク]]
```

のように記法が入れ子になったとき、置換では対応する括弧を見つけられず破綻するため。
角括弧は深さを数えて対応を取る。

### 1行 = 1要素

パース結果は、入力の行数と必ず一致する。
カーソルのある行だけをテキストに戻すため（11.6）、行と表示が1対1でないと成立しない。

箇条書きの階層は入れ子の `<ul>` ではなく、各行の字下げを CSS の余白で表す。
Scrapbox 自身も行単位で描画しており、この方が編集との相性がよい。

- **行**: 通常行 / 引用 / `code:` の行 / コードブロックの中身
- **インライン**: 行の中身。装飾・リンク・画像・コード・ハッシュタグ

角括弧の中身は、次の順で判定する。

1. `[[...]]` → 画像 URL なら大きい画像、それ以外は強調
2. 装飾記号＋空白で始まる → 文字装飾
3. 2語で「画像URL＋URL」→ リンク付き画像
4. 先頭または末尾が URL → リンク
5. 単体が画像 URL → 画像
6. 単体が URL → リンク
7. それ以外 → ページリンク

## 11.6 編集 UI

Notion のような WYSIWYG にはしない。Scrapbox と同じく、
**記法を含むプレーンテキストを直接編集する**。

### 行単位で切り替える

Scrapbox と同じく、**行ごとに**表示を切り替える。

| 行 | 表示 |
|---|---|
| カーソルのある行 | 記法をそのままのテキストとして編集 |
| それ以外の行 | 記法を解釈した表示 |

本文全体を一度にテキストへ戻さない。書いている場所の記法だけが見え、
周りは仕上がりのまま読めるので、書きながら全体を確認できる。

そのため、**パーサーは1行が必ず1要素に対応する構造**にしている
（11.5）。行と表示がずれると、カーソル行だけを差し替えられない。

### キー操作

| キー | 動作 |
|---|---|
| クリック / `y` | その行の編集に切り替える |
| `Enter` | 行を分割する。前の行の字下げを引き継ぐ |
| `Backspace`（行頭） | 前の行と結合する |
| `↑` `↓`（行端） | 前後の行へ移る |
| `Tab` / `Shift`+`Tab` | 字下げを1段増やす / 減らす |
| `Esc` | 編集をやめて表示に戻す |

日本語入力の変換中は `Enter` を横取りしない。変換の確定が行の分割として
扱われてしまうため、`compositionstart` / `compositionend` で判定する。

保存されるのは常に入力したままのテキスト。
将来、入力補助を足すことはできるが、保存するデータは変えない。

## 11.7 画像とS3

画像本体は S3 に置く（[03-functional-spec.md](03-functional-spec.md) 3.5）。
本文からは、Scrapbox の画像記法（角括弧のURL）で参照する。

```text
[/images/<画像ID>.png]
```

### なぜアプリからの相対パスか

- **独自記法を作らない** — Scrapbox の `[画像URL]` の形をそのまま使えるため、
  記法の一貫性が保てる
- **ホスト名を本文に埋め込まない** — 絶対 URL で保存すると、ドメインを変えたときに
  全ての本文を書き換えることになる。長期利用とデータの持ち出しやすさを重視する方針
  （[05-operations.md](05-operations.md)）に反する
- **エクスポート時は接頭辞を置換するだけで済む** — `/images/` を配布先の URL に
  置き換えれば、他のツールでも画像が解決できる

> **トレードオフ:** Scrapbox では `/プロジェクト名/ページ名` が別プロジェクトへの
> リンクを意味するため、`/images/...` は記法として衝突する。
> このサービスにプロジェクトの概念がないため、実害はないと判断して受け入れる。

### アップロードの流れ（Milestone 8）

1. S3 へ画像をアップロードする
2. 画像を識別する ID を得る
3. 本文へ `[/images/<ID>.<拡張子>]` を挿入する
4. 表示時に S3 の URL へ解決する

## 11.8 保存するもの

DB に入るのは、**ユーザーが入力したテキストそのまま**。

- HTML は保存しない
- リッチテキスト JSON も保存しない
- 記法の正規化もしない

表示のたびに変換する。変換結果を保存しないので、記法の解釈を後から変えても
過去の本文がそのまま生き続ける。

---

## 11.9 XSS 対策

本文はユーザーが書いた文字列であり、そのまま HTML にすると危険。

- **すべてのテキストをエスケープしてから**組み立てる（`&<>"'`）
- `href` / `src` に入れる URL は、`http(s)://` とアプリ相対パスだけを通す。
  `javascript:` などは通さず、リンクにせずテキストとして出す
- コードブロック・インラインコードの中身も同じくエスケープする

レンダラの出力は上記を満たしたうえで組み立てているため、表示側で `v-html` を使ってよい。

### 確認した入力

| 入力 | 結果 |
|---|---|
| `<script>alert(1)</script>` | エスケープされて文字として表示 |
| `[<img src=x onerror=alert(1)> https://example.com]` | タグがエスケープされ、リンクのテキストになる |
| `[javascript:alert(1) クリック]` | リンクにならない |
| `[javascript:alert(1).png]` | 画像にならない |
