# 08. TODO 管理機能（Remember The Milk 的な使い勝手）

クイックメモ（[06-roadmap.md](06-roadmap.md) Milestone 2）が完成した後に実装する、TODO 管理としての本体機能。

**目標は Remember The Milk（以下 RTM）と同等の操作感。** マウスをほとんど使わず、キーボードだけで一覧を捌けることを重視する。

要件は以下の3点。

1. 重要度順 → 期限日順にソートできる
2. RTM と同様のキーボードショートカットで各種編集操作ができる
3. RTM と同様の SmartAdd 機能

---

## 8.1 データモデルへの影響

重要度を保持するため、**`items` に `priority` カラムを追加する**。これは [02-data-model.md](02-data-model.md) に反映済み。

| カラム | 型 | 必須 | 説明 |
|---|---|---|---|
| priority | smallint | No | 1（高） / 2（中） / 3（低）。NULL は「重要度なし」 |

- RTM に合わせ、値が小さいほど重要度が高い
- 「重要度なし」は `NULL` とし、ソート時は最後に置く
- `CHECK (priority BETWEEN 1 AND 3)` で値域を制限する

`due_at`（期限）は既存カラムをそのまま使う。作業日は `Section.date` であり、期限とは別概念（[02-data-model.md](02-data-model.md) 2.3）。

### 一覧での表示

RTM に倣い、**一覧の各行の左端に重要度の色を帯で出す**。並びが重要度順でも、
どこまでが「高」なのかは読まないと分からないため、色で境目が見えるようにする。

| 重要度 | 色 | 変数 |
|---|---|---|
| 1（高） | 赤 | `--priority-1` |
| 2（中） | 青 | `--priority-2` |
| 3（低） | 水色 | `--priority-3` |
| なし | 灰色 | `--priority-none` |

重要度なしも灰色の帯を出す。帯そのものが消えると、色が付いていないのか
帯が無いのかを区別できないため。

色だけで判断させないよう、**「重要度高」の文字表示は残す**。
色覚特性や、白黒印刷（[05-operations.md](05-operations.md) のエクスポート）でも
重要度が分かる必要がある。

一覧のカーソル位置（`j` / `k` の対象）は、左端ではなく**囲みの線**で示す。
左端は重要度に使うため。

## 8.2 ソート

### 既定のソート順

```sql
ORDER BY
  priority ASC NULLS LAST,
  due_at   ASC NULLS LAST,
  created_at ASC
```

重要度が高いものが上、同じ重要度の中では期限が近いものが上。
重要度なし・期限なしはそれぞれ末尾に送る。`created_at` は同値時の順序を安定させるため。

### 切り替え可能なソート軸

| 軸 | 順序 |
|---|---|
| 重要度順（既定） | `priority` → `due_at` 昇順 → `created_at` |
| 重要度順（期限は新しい順） | `priority` → `due_at` **降順** → `created_at` |
| 期限日順 | `due_at` → `priority` → `created_at` |
| 追加日順 | `created_at` 降順 |
| タイトル順 | `title` |

ソート軸は画面ごとに localStorage で記憶する。

## 8.3 「今日」リスト

その日に手をつけるべきものだけを集めた一覧。一覧を開いた最初の判断を速くするため、
条件を絞って表示する。

### 対象

| 条件 | 内容 |
|---|---|
| 期限 | **今日の 23:59:59 まで**（期限切れを含む） |
| 期限なし | 含めない。いつやるか決まっていないため |
| 未来の期限 | 含めない |
| 完了済み | 含めない |

日付の境界はアプリのタイムゾーン（Asia/Tokyo）で判定する。
実行環境が UTC でもずれないよう、オフセットを明示して境界を組み立てる。

### 並び

既定は **重要度順 → 期限の降順**。

```sql
ORDER BY
  priority ASC NULLS LAST,
  due_at   DESC,
  created_at ASC
```

期限を降順にするため、同じ重要度の中では**今日のものが上、古い期限切れが下**に来る。
ソート軸は他の一覧と同じく切り替えられる。

### インデックス

```sql
CREATE INDEX items_priority_due_idx
  ON items (priority ASC NULLS LAST, due_at ASC NULLS LAST);
```

個人利用のためデータ量は小さいが、既定のソートに合わせて用意しておく。

### 期限の表示

RTM に倣い、絶対日付ではなく相対表現を優先する。

```text
今日 / 明日 / 木曜日 / 8月25日 / 昨日 / 3日前 / 8月10日
```

「期限切れ」の文字は出さない。1日前は「昨日」、2〜7日前は「○日前」、
それ以前は絶対日付（同年なら月日のみ、年をまたぐなら年も出す）で表す。
期限切れは視覚的に強調する。

## 8.4 キーボードショートカット

### 基本方針

- 一覧に「選択中のタスク」というカーソル状態を持たせ、そのタスクに対してキー操作を適用する
- 単一キーで発火する（修飾キーを極力使わない）
- 入力欄にフォーカスがある間はショートカットを無効化する
- 破壊的操作は `u`（Undo）で取り消せるようにする

### 割り当て

RTM の[キーボードショートカット](https://www.rememberthemilk.com/help/?ctx=basics.basics.keyboard)に合わせる。
同じ操作は同じキーにし、RTM から持ち替えても手が迷わないようにする。

| キー | 操作 | RTM での名称 |
|---|---|---|
| `t` | タスクを追加（入力欄へ移る） | タスクを追加 |
| `j` / `↓` | 次のタスクへ | |
| `k` / `↑` | 前のタスクへ | |
| `h` | 完了 / 未完了を切り替え | 完了/未完了を切り替え |
| `o` / `Enter` | タスクを開く | タスクを開く |
| `i` | タスクを選択（複数選択） | タスクを選択 |
| `c` | 完了にする | 完了 |
| `p` | 期限を明日にする | 延期 / 1日延期 |
| `d` | 期日を変更 | 期日を変更 |
| `f` | くり返し設定を変更 | くり返し設定を変更 |
| `1` / `2` / `3` | 優先度を 1 / 2 / 3 に設定 | 同左 |
| `4` | 優先度を設定しない | 優先度を設定しない |
| `s` | タグを変更 | タグを変更 |
| `r` | 名称を変更 | 名称変更 |
| `u` | URL を変更 | URLを変更 |
| `Shift` + `u` | URL を開く | URLを開く |
| `y` | ノートを追加（本文へ移る） | ノートの追加 |
| `Shift` + `y` | 今日の作業記録を書く | |
| `z` | 元に戻す | 元に戻す |
| `Delete` / `Backspace` | 削除 | |
| `/` | 検索へ移る（[03-functional-spec.md](03-functional-spec.md) 3.6） | |
| `?` | ショートカット一覧を表示 | |
| `Esc` | 編集・選択・ダイアログをキャンセル | |

複数タスクを `i` で選択している場合、`c` / `1` / `d` などの操作は選択中の全タスクに適用する。

`t` はどの画面でも効く。入力欄のある画面（今日 / Inbox / タスク）ではその欄へ移り、
入力欄のない画面（日記・検索・詳細）からは Inbox へ移ってから入力欄へ移る。
思いついたことを書き留める場所は Inbox なので、行き先に迷わせない。

### スマートフォンでの追加（右下の「＋」）

狭い画面（40rem 以下）では入力欄を常に置かず、右下に固定した「＋」から開く。
一覧に使える高さを増やすため。押すと入力欄が下端から重なって出てきて、
そのままキーボードが立ち上がる。追加すると閉じ、一覧に戻る。

- `t` と同じ入り口（app.vue の `addTask`）。入力欄のない画面（日記・検索・詳細）
  からは Inbox へ移ってから開く
- 閉じるのは「閉じる」・背景のタップ・`Esc`
- 広い画面はこれまでどおり入力欄を常に出す。書くことが目的の画面
  （共有の受付。[13-share-target.md](13-share-target.md)）は幅に関わらず常に出す

#### 期限・重要度を選ぶボタン

狭い画面では、入力欄の下に「期限 / 重要度 / タグ / 繰り返し」のボタンを置く
（RTM の追加画面と同じ形）。記号（`^` `!` `#` `*`）を打つのが手間で、
ソフトウェアキーボードでは記号の入力に切り替えが要るため。

- 開く画面は一覧での設定（`d` / `s` / `*`）と同じもの。覚えることを増やさない
- 重要度は選択肢が4つ（高 / 中 / 低 / なし）しかないので、その場で行を広げる
- 選んだ内容は **SmartAdd の記法としてテキストへ書き戻す**
  （`composeSmartAddInput`）。追加の経路をテキスト1本に保てるので、
  共有の受付・オフラインの送信列・サーバーのどれにも手を入れずに済む
- テキストに書いた記法とボタンで選んだ内容が重なった場合は、ボタンが優先。
  書き戻す際にタイトルを組み立て直すので、記法が二重にならない
- 選んだ内容はプレビューの札に出る。ボタン自身も設定済みの色に変わる
- 広い画面には出さない。記法を打つほうが速く、ヒントも出している

#### 複数行（1行目がタイトル、2行目以降が本文）

狭い画面では、`multiline` の指定に関わらず複数行を受け付ける。
キーボードの改行を送信に使ってしまうと、本文を書く手段が無くなるため。
送信は「追加」ボタン（広い画面は `Enter` または `⌘ + Enter`）で行う。

1行目がタイトル、2行目以降が作成日の Section の本文になる（`splitInput`）。
一覧の入力欄・共有の受付・サーバーで同じ分け方をする。

**画面を開いただけでは、どの画面も入力欄にフォーカスしない。**
フォーカスされていると一覧のキーボード操作が入力欄に吸われ、
`j` / `k` すら効かなくなる。書き始めるのは `t` を押したときだけにする。

### 完了の表示（`h`）

RTM の「未完了 / 完了」の切り替えと同じ。いまの絞り込み（タグ・期限）はそのままに、
完了したものだけを出す。やったことを見返す導線を画面ごとに作らず、一覧を裏返して見せる。

- 状態は URL（`?completed=true`）に残す。再読み込みや共有で同じ表示に戻せる
- 完了側では `c` が「未完了に戻す」になる。見ている一覧で要る操作が逆になるため
- 一覧の右上にも「未完了 / 完了」を出す。キーボードを使わなくても切り替えられ、
  いまどちら側を見ているかが分かるようにする
- タスク画面の status タブは、完了を見ている間「完了」に追従する。
  一覧と選ばれているタブが食い違って見えないようにする

`status` は進行状態を1つだけ持つ値なので、完了したものは Inbox でも Backlog でもなくなる。
そのため完了側では画面の status を見ない。Inbox で `h` を押すと、
タグの絞り込みに合う完了タスクがすべて出る。

### 画面の移動（`g`）

RTM に合わせ、画面の移動は `g` を押してから行き先のキーを押す。
単独キーは一覧の操作に使い切っており、移動に割ける文字が残っていないため。

| キー | 移動先 | RTM での名称 |
|---|---|---|
| `g` `t` | 今日 | Go to Today |
| `g` `i` | Inbox | Go to Inbox |
| `g` `s` | タグ一覧（[09-tags.md](09-tags.md) 9.3） | Go to Tags |

- `g` を押したあと 1.5 秒以内に次を押さなければ、押したことは忘れる
- 続きに割り当てのないキーを押した場合は、何もせずに待ちを解く。
  `g` のあとの `c`（完了）のように、移動のつもりが編集になるのを防ぐため
- 移動系も `t` と同じく、一覧以外の画面からでも効く

### RTM にあるが割り当てないもの

対応する機能を持たないため、キーを割り当てない。

| キー | RTM での操作 | 理由 |
|---|---|---|
| `w` | 開始日を変更 | 開始日を持たない（期限のみ） |
| `e` | 予測時間を変更 | 見積もりを持たない |
| `!` | 優先度を変更 | `1`〜`4` で直接指定できる |
| `m` | リストを変更 | リストの概念がない。役割はタグが担う |
| `l` | 場所を変更 | 場所を持たない |
| `v` | 担当者変更 | 単一ユーザー |
| `b` | リマインダーをセット | 通知を持たない |

### 以前の割り当てからの変更

RTM に合わせる前は独自の割り当てだった。特に **`u` は取り消しに使っていたが、
RTM では「URLを変更」**であり、取り消しは `z`。手が覚えている操作ほど
食い違いが事故になるため、RTM 側にそろえた。

| 操作 | 変更前 | 変更後 |
|---|---|---|
| 元に戻す | `u` | `z` |
| URL を変更 | （なし） | `u` |
| タスクを選択 | `x` | `i` |
| タスクを開く | `Enter` | `o`（`Enter` も残す） |
| タグを変更 | `t` / `Shift` + `t` | `s` |
| くり返し設定 | `r` | `f` |
| 名称を変更 | （なし） | `r` |
| タスクを追加 | （なし） | `t`（タグ変更から空いた） |

### 実装上の注意

- ショートカット一覧（`?`）は、割り当てを定義したテーブルから自動生成する。実装とヘルプがずれないようにする
- `r` / `u` / `y` は詳細の各欄へ移る。分割表示なら右ペイン、狭い画面では詳細画面へ移動する
- `j` / `k` でカーソルが動いたら、その行が見えるところまで一覧をスクロールする。
  送っているうちに画面外へ出ると、どこを操作しているのか分からなくなるため
- 定義の登録は画面ごとに分かれてよいが（一覧は一覧が、`t` / `g` は app.vue が持つ）、
  打鍵の解釈は1つにまとめる。別々に窓を監視すると、`g` を待っている登録と
  待っていない登録ができ、`g` `s`（タグへ移動）が `s`（タグを変更）も走らせる

### スマートフォンでの扱い

キーボードショートカットは PC 専用。スマートフォンではスワイプ操作・長押しメニューで同等の操作を提供する。

## 8.5 SmartAdd

1行のテキスト入力から、タイトル・期限・重要度をまとめて指定できるようにする。

### 構文

RTM の記法に準拠する。

| 記号 | 意味 | 例 | 実装 |
|---|---|---|---|
| `^` | 期限 | `^tomorrow` `^明日` `^8/25` `^金曜` | Milestone 3 |
| `!` | 重要度 | `!1` `!2` `!3` | Milestone 3 |
| `#` | タグ | `#買い物` `#急ぎ` | Milestone 4（[09-tags.md](09-tags.md) 9.4） |
| `*` | 繰り返し | `*every week` `*毎週月曜` `*after 3 days` | Milestone 5（[10-recurrence.md](10-recurrence.md) 10.7） |

記号の前後の空白は許容し、記号として解釈された部分はタイトルから取り除く。

```text
入力:  請求書を出す ^明日 !1
結果:  title    = "請求書を出す"
       due_at   = 翌日
       priority = 1
```

```text
入力:  牛乳を買う
結果:  title    = "牛乳を買う"
       due_at   = NULL
       priority = NULL
```

### 対応しない記法

| 記号 | RTM での意味 | 対応しない理由 |
|---|---|---|
| `@` | 場所 | 用途がない |
| `=` | 時間見積もり | 用途がない |

未実装の記号は**予約扱いとし、解釈せずタイトルの一部として残す**。
後から対応を追加しても、過去データの解釈が変わらないようにするため。

### 日付のパース

`^` の後ろは自然言語の日付表現を受け付ける。日本語・英語の両方に対応する。

- [chrono-node](https://github.com/wanasit/chrono) を使う（日本語ロケール対応あり）
- パーサは `shared/utils/smart-add.ts` に置き、**サーバーとクライアントで同じコードを動かす**。
  入力中のプレビューと保存結果が食い違わないようにするため
- タイムゾーンは Asia/Tokyo 固定とする（個人利用のため）。
  Vercel の実行環境は UTC なので、Nitro プラグインで `process.env.TZ` を設定する

#### chrono だけでは足りない部分

実装時に判明した、補いが必要なもの。

| 表現 | chrono 単体での挙動 | 対応 |
|---|---|---|
| `来週の水曜` | 「来週の」を読み飛ばし、**今週の水曜**を返す | 前置詞で基準日を来週の月曜へずらしてから chrono に渡す |
| `来月の15日` | 解釈できない | 基準日を来月1日にずらし、裸の「15日」を自前で解釈する |
| `来週` `月末` `週末` | 解釈できない | 独自の相対表現として解決する |

特に「来週の水曜」は、**誤りに気づけないまま今週の日付が入る**のが問題だった。
解釈できない場合に何も設定しないより害が大きいため、前置詞を先に処理する構造にしている。

#### 裸の URL は URL 欄へ

タイトルに `https://...` をそのまま書くと、**Item の URL 欄**へ取り込み、
タイトルからは取り除く。

```text
入力:  資料を読む https://example.com/doc !1
結果:  title = "資料を読む"
       url   = "https://example.com/doc"
```

タイトルに URL が並んでいると読みにくく、一覧から開く導線もないため。
取り込むのは最初の1つだけ。

#### 期限を書かなかった場合

**期限の指定がなければ今日にする。**

追加したタスクが「今日」リストに出ないまま埋もれるのを避けるため。
期限を持たせたくない場合は、追加後に詳細から外す。

入力欄には、何も書かなければ今日になることを常に表示する。

#### 時刻の扱い

時刻の指定がない場合は、その日の 23:59 を期限として保存し、`due_has_time` を false にする。
表示では日付だけを見せ、期限切れの判定も日付単位で行う。

```text
^明日        → 明日 23:59, due_has_time = false → 「明日」と表示
^明日15時    → 明日 15:00, due_has_time = true  → 「明日 15:00」と表示
```

### 入力中のフィードバック

パース結果をリアルタイムに表示し、意図しない解釈を防ぐ。

```text
┌────────────────────────────────────┐
│ 請求書を出す ^明日 !1               │
└────────────────────────────────────┘
  → 請求書を出す ・ 期限 8/19(火) ・ 重要度 高
```

解釈できなかった `^` の後ろは、そのままタイトルに残したうえで警告を出す。

### ボタンから選んだ内容の書き戻し

狭い画面のボタン（8.4）で選んだ期限・重要度・タグ・繰り返しは、
`composeSmartAddInput` が SmartAdd の記法に直してテキストへ書き戻す。

```text
入力:  牛乳を買う
選択:  期限 2026/09/03・重要度 高
送信:  牛乳を買う !1 ^2026/09/03
```

- 期限は「明日」ではなく絶対表記にする。書きかけのまま日付をまたいでも
  指すものが変わらないようにするため
- タイトルは `parseSmartAdd` が記法を取り除いた結果から組み立て直す。
  テキストに書いた記法とボタンで選んだ内容が二重にならない
- 繰り返しは空白を含む（「毎週 月曜」）ので、他の記号より後ろに置く
- 何も選んでいなければ書き換えない。ボタンを使わない限り、
  入力したテキストがそのまま送られる
