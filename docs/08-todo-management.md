# 08. TODO 管理機能（Remember The Milk 的な使い勝手）

クイックメモ（[06-roadmap.md](06-roadmap.md) Milestone 2）が完成した後に実装する、TODO 管理としての本体機能。

**目標は Remember The Milk（以下 RTM）と同等の操作感。** マウスをほとんど使わず、キーボードだけで一覧を捌けることを重視する。

要件は以下の3点。

1. 重要度順 → 期限日順にソートできる
2. RTM と同様のキーボードショートカットで各種編集操作ができる
3. RTM と同様の SmartAdd 機能

---

## 8.1 データモデルへの影響

重要度を保持するため、**`items` に `priority` カラムを追加する**。これは [02-data-model.md](02-data-model.md) に反映済み。

| カラム | 型 | 必須 | 説明 |
|---|---|---|---|
| priority | smallint | No | 1（高） / 2（中） / 3（低）。NULL は「重要度なし」 |

- RTM に合わせ、値が小さいほど重要度が高い
- 「重要度なし」は `NULL` とし、ソート時は最後に置く
- `CHECK (priority BETWEEN 1 AND 3)` で値域を制限する

`due_at`（期限）は既存カラムをそのまま使う。作業日は `Section.date` であり、期限とは別概念（[02-data-model.md](02-data-model.md) 2.3）。

## 8.2 ソート

### 既定のソート順

```sql
ORDER BY
  priority ASC NULLS LAST,
  due_at   ASC NULLS LAST,
  created_at ASC
```

重要度が高いものが上、同じ重要度の中では期限が近いものが上。
重要度なし・期限なしはそれぞれ末尾に送る。`created_at` は同値時の順序を安定させるため。

### 切り替え可能なソート軸

| 軸 | 順序 |
|---|---|
| 重要度順（既定） | `priority` → `due_at` 昇順 → `created_at` |
| 重要度順（期限は新しい順） | `priority` → `due_at` **降順** → `created_at` |
| 期限日順 | `due_at` → `priority` → `created_at` |
| 追加日順 | `created_at` 降順 |
| タイトル順 | `title` |

ソート軸は画面ごとに localStorage で記憶する。

## 8.3 「今日」リスト

その日に手をつけるべきものだけを集めた一覧。一覧を開いた最初の判断を速くするため、
条件を絞って表示する。

### 対象

| 条件 | 内容 |
|---|---|
| 期限 | **今日の 23:59:59 まで**（期限切れを含む） |
| 期限なし | 含めない。いつやるか決まっていないため |
| 未来の期限 | 含めない |
| 完了済み | 含めない |

日付の境界はアプリのタイムゾーン（Asia/Tokyo）で判定する。
実行環境が UTC でもずれないよう、オフセットを明示して境界を組み立てる。

### 並び

既定は **重要度順 → 期限の降順**。

```sql
ORDER BY
  priority ASC NULLS LAST,
  due_at   DESC,
  created_at ASC
```

期限を降順にするため、同じ重要度の中では**今日のものが上、古い期限切れが下**に来る。
ソート軸は他の一覧と同じく切り替えられる。

### インデックス

```sql
CREATE INDEX items_priority_due_idx
  ON items (priority ASC NULLS LAST, due_at ASC NULLS LAST);
```

個人利用のためデータ量は小さいが、既定のソートに合わせて用意しておく。

### 期限の表示

RTM に倣い、絶対日付ではなく相対表現を優先する。

```text
今日 / 明日 / 木曜日 / 8月25日 / 期限切れ（3日前）
```

期限切れは視覚的に強調する。

## 8.4 キーボードショートカット

### 基本方針

- 一覧に「選択中のタスク」というカーソル状態を持たせ、そのタスクに対してキー操作を適用する
- 単一キーで発火する（修飾キーを極力使わない）
- 入力欄にフォーカスがある間はショートカットを無効化する
- 破壊的操作は `u`（Undo）で取り消せるようにする

### 割り当て

RTM の[キーボードショートカット](https://www.rememberthemilk.com/help/?ctx=basics.basics.keyboard)に合わせる。
同じ操作は同じキーにし、RTM から持ち替えても手が迷わないようにする。

| キー | 操作 | RTM での名称 |
|---|---|---|
| `j` / `↓` | 次のタスクへ | |
| `k` / `↑` | 前のタスクへ | |
| `o` / `Enter` | タスクを開く | タスクを開く |
| `i` | タスクを選択（複数選択） | タスクを選択 |
| `c` | 完了にする | 完了 |
| `p` | 期限を明日にする | 延期 / 1日延期 |
| `d` | 期日を変更 | 期日を変更 |
| `f` | くり返し設定を変更 | くり返し設定を変更 |
| `1` / `2` / `3` | 優先度を 1 / 2 / 3 に設定 | 同左 |
| `4` | 優先度を設定しない | 優先度を設定しない |
| `s` | タグを変更 | タグを変更 |
| `r` | 名称を変更 | 名称変更 |
| `u` | URL を変更 | URLを変更 |
| `Shift` + `u` | URL を開く | URLを開く |
| `y` | ノートを追加（本文へ移る） | ノートの追加 |
| `Shift` + `y` | 今日の作業記録を書く | |
| `z` | 元に戻す | 元に戻す |
| `Delete` / `Backspace` | 削除 | |
| `/` | 検索へ移る（[03-functional-spec.md](03-functional-spec.md) 3.6） | |
| `?` | ショートカット一覧を表示 | |
| `Esc` | 編集・選択・ダイアログをキャンセル | |

複数タスクを `i` で選択している場合、`c` / `1` / `d` などの操作は選択中の全タスクに適用する。

### RTM にあるが割り当てないもの

対応する機能を持たないため、キーを割り当てない。

| キー | RTM での操作 | 理由 |
|---|---|---|
| `w` | 開始日を変更 | 開始日を持たない（期限のみ） |
| `e` | 予測時間を変更 | 見積もりを持たない |
| `!` | 優先度を変更 | `1`〜`4` で直接指定できる |
| `m` | リストを変更 | リストの概念がない。役割はタグが担う |
| `l` | 場所を変更 | 場所を持たない |
| `v` | 担当者変更 | 単一ユーザー |
| `b` | リマインダーをセット | 通知を持たない |

### 以前の割り当てからの変更

RTM に合わせる前は独自の割り当てだった。特に **`u` は取り消しに使っていたが、
RTM では「URLを変更」**であり、取り消しは `z`。手が覚えている操作ほど
食い違いが事故になるため、RTM 側にそろえた。

| 操作 | 変更前 | 変更後 |
|---|---|---|
| 元に戻す | `u` | `z` |
| URL を変更 | （なし） | `u` |
| タスクを選択 | `x` | `i` |
| タスクを開く | `Enter` | `o`（`Enter` も残す） |
| タグを変更 | `t` / `Shift` + `t` | `s` |
| くり返し設定 | `r` | `f` |
| 名称を変更 | （なし） | `r` |

### 実装上の注意

- ショートカット一覧（`?`）は、割り当てを定義したテーブルから自動生成する。実装とヘルプがずれないようにする
- `r` / `u` / `y` は詳細の各欄へ移る。分割表示なら右ペイン、狭い画面では詳細画面へ移動する
- `j` / `k` でカーソルが動いたら、その行が見えるところまで一覧をスクロールする。
  送っているうちに画面外へ出ると、どこを操作しているのか分からなくなるため

### スマートフォンでの扱い

キーボードショートカットは PC 専用。スマートフォンではスワイプ操作・長押しメニューで同等の操作を提供する。

## 8.5 SmartAdd

1行のテキスト入力から、タイトル・期限・重要度をまとめて指定できるようにする。

### 構文

RTM の記法に準拠する。

| 記号 | 意味 | 例 | 実装 |
|---|---|---|---|
| `^` | 期限 | `^tomorrow` `^明日` `^8/25` `^金曜` | Milestone 3 |
| `!` | 重要度 | `!1` `!2` `!3` | Milestone 3 |
| `#` | タグ | `#買い物` `#急ぎ` | Milestone 4（[09-tags.md](09-tags.md) 9.4） |
| `*` | 繰り返し | `*every week` `*毎週月曜` `*after 3 days` | Milestone 5（[10-recurrence.md](10-recurrence.md) 10.7） |

記号の前後の空白は許容し、記号として解釈された部分はタイトルから取り除く。

```text
入力:  請求書を出す ^明日 !1
結果:  title    = "請求書を出す"
       due_at   = 翌日
       priority = 1
```

```text
入力:  牛乳を買う
結果:  title    = "牛乳を買う"
       due_at   = NULL
       priority = NULL
```

### 対応しない記法

| 記号 | RTM での意味 | 対応しない理由 |
|---|---|---|
| `@` | 場所 | 用途がない |
| `=` | 時間見積もり | 用途がない |

未実装の記号は**予約扱いとし、解釈せずタイトルの一部として残す**。
後から対応を追加しても、過去データの解釈が変わらないようにするため。

### 日付のパース

`^` の後ろは自然言語の日付表現を受け付ける。日本語・英語の両方に対応する。

- [chrono-node](https://github.com/wanasit/chrono) を使う（日本語ロケール対応あり）
- パーサは `shared/utils/smart-add.ts` に置き、**サーバーとクライアントで同じコードを動かす**。
  入力中のプレビューと保存結果が食い違わないようにするため
- タイムゾーンは Asia/Tokyo 固定とする（個人利用のため）。
  Vercel の実行環境は UTC なので、Nitro プラグインで `process.env.TZ` を設定する

#### chrono だけでは足りない部分

実装時に判明した、補いが必要なもの。

| 表現 | chrono 単体での挙動 | 対応 |
|---|---|---|
| `来週の水曜` | 「来週の」を読み飛ばし、**今週の水曜**を返す | 前置詞で基準日を来週の月曜へずらしてから chrono に渡す |
| `来月の15日` | 解釈できない | 基準日を来月1日にずらし、裸の「15日」を自前で解釈する |
| `来週` `月末` `週末` | 解釈できない | 独自の相対表現として解決する |

特に「来週の水曜」は、**誤りに気づけないまま今週の日付が入る**のが問題だった。
解釈できない場合に何も設定しないより害が大きいため、前置詞を先に処理する構造にしている。

#### 裸の URL は URL 欄へ

タイトルに `https://...` をそのまま書くと、**Item の URL 欄**へ取り込み、
タイトルからは取り除く。

```text
入力:  資料を読む https://example.com/doc !1
結果:  title = "資料を読む"
       url   = "https://example.com/doc"
```

タイトルに URL が並んでいると読みにくく、一覧から開く導線もないため。
取り込むのは最初の1つだけ。

#### 期限を書かなかった場合

**期限の指定がなければ今日にする。**

追加したタスクが「今日」リストに出ないまま埋もれるのを避けるため。
期限を持たせたくない場合は、追加後に詳細から外す。

入力欄には、何も書かなければ今日になることを常に表示する。

#### 時刻の扱い

時刻の指定がない場合は、その日の 23:59 を期限として保存し、`due_has_time` を false にする。
表示では日付だけを見せ、期限切れの判定も日付単位で行う。

```text
^明日        → 明日 23:59, due_has_time = false → 「明日」と表示
^明日15時    → 明日 15:00, due_has_time = true  → 「明日 15:00」と表示
```

### 入力中のフィードバック

パース結果をリアルタイムに表示し、意図しない解釈を防ぐ。

```text
┌────────────────────────────────────┐
│ 請求書を出す ^明日 !1               │
└────────────────────────────────────┘
  → 請求書を出す ・ 期限 8/19(火) ・ 重要度 高
```

解釈できなかった `^` の後ろは、そのままタイトルに残したうえで警告を出す。

### クイックメモとの関係

Milestone 2 のクイックメモ入力欄でも SmartAdd を有効にする。
ただしクイックメモは「素早く投げ込む」ことが目的なので、記法を知らなくても普通の文章として書けることを維持する（記号がなければ全文がタイトル、または2行目以降が Section の本文）。
